ما هو: تطبيق مستقل للفحص الفني للمركبات — واجهة + خلفية في ريبو واحد. قاعدة بياناته مشروع Supabase واحد DASM-services (bmfqfmsxtotdksvcqfrh) يحوي كل جداول inspection_*، ويشير إلى DASM-core (ttkhiatwayvlfksvehzm) للمستخدمين والسيارات بالمرجع فقط.

الحكم على «التشوّه»: بنيةً الريبو متماسك أكثر مما يبدو — لا روابط مكسورة، لا مسارات مكرّرة، كل مفاتيح التنقّل لها صفحات. الإحساس بالتشوّه مصدره أربعة أمور، عولج أهمها: (1) كسر القشرة (رابط داخل اللوحة يقذف للموقع العام) — أُصلح بـ PR #70؛ (2) ضعف اكتشاف صفحات التفاصيل — تصميم مقبول؛ (3) فجوات الوضع الداكن — متبقٍّ؛ (4) وثائق قديمة/مفقودة — متبقٍّ.
تحديث 2026-07-07 — ✅ خطة إعادة الربط مكتملة: مزامنة Core (#72) · الوضع الداكن (#73) · تطابق نوع السوق (#74) · حدّ معدّل المصادقة (#76) · تنظيف الوثائق (#78) · فحص البيئة عند الإقلاع (#77) · القشرة التكيّفية (#70). المتبقّي الوحيد إجراء تشغيلي: تأكيد متغيّرات البيئة على Vercel.

7 · المصادقة والهوية والكوكيز

  • استخراج التوكن: Bearer ثم كوكي (dasm_access_token / inspection_token).
  • مساران: تحقّق JWT (HS256/JWKS) عند DASM_JWT_ENFORCE=true؛ واحتياط تحقّق Sanctum عبر /api/user/profile.
  • الشخصية: من ترويسات موثّقة يضبطها الوسيط (ثقة jwt) أو كوكيز البوابة (ثقة gateway_cookie).
  • الكوكيز: inspection_dasm_user_id · inspection_ui_role (عرض فقط — لا يُعتمد أمنياً) · كوكيز Supabase.
  • الوسيط: يعقّم الترويسات الداخلية (منع الانتحال) · يحدّث جلسة Supabase · يعفي /, /auth/, /workshops/, /track/.

9 · «مالنا وما علينا»

✅ مالنا (أصول تعمل)

  • تدفّق فحص كامل: إنشاء → إسناد → تنفيذ (ورشة/ميداني) → تقرير → اعتماد/رفض، مع سجلّ ومرفقات.
  • لوحة ورشة كاملة (فريق، أسعار، مناطق، ميداني، تقييمات، متابعون، تصدير) مربوطة.
  • خزنة سجلّ المركبة + تذكيرات · توصيات إصلاح + محادثة داخل الطلب.
  • تكامل منصّة: SSO + بوابة + REST v1 + طبقة جوال كاملة.
  • هوية موحّدة + خروج + فوتر + قانوني + محفظة + وضع داكن + قشرة تكيّفية (#70).
  • بنية سليمة: لا روابط مكسورة، لا تكرار، RLS مقفل.
